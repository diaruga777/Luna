# Reading List & Ingestion

Clip is a weblink reader: links saved from Safari (extension + intent) or pasted in-app are downloaded, stripped to readable text, and read in two reader modes.

> **Note:** the reader-shared models + ingest helpers moved to `ReaderKit/`
> (shared with the ClipShare target): `ReadingListItem`, `ReadingListStore`,
> `ArticleContent`, `ArticleFetcher`, `ArticleExtractor`. Paths below that say
> `Clip/ReadingList/...` for those files now live under `ReaderKit/`. See
> `readers.md`.

## Key files

- `Clip/ReadingList/ReadingListItem.swift` — model. Content state: `pending → ready | failed` (failed retries on launch/foreground/pull-to-refresh). Read state: `unopened → opened → read` (never downgrades). `lastReaderMode` remembers scroll vs rsvp per article. Decoding defaults `readState` for pre-existing items.
- `Clip/ReadingList/ReadingListStore.swift` — JSON persistence in the App Group container (`group.com.hpiddy.clip`): `readingList.json` + `Articles/<uuid>.json` per article. Shared with the intent process. Posts `Notification.Name.readingListChanged` on every mutation. Reads disk fresh per call (simple over fast). Mutations are TARGETED (setLastWordIndex/markFailed/markReadState/setReaderMode/saveContent fetch fresh and set single fields) — whole-item writes from stale copies silently reverted other screens' fields.
- `Clip/ReadingList/ReadingListIngestor.swift` — fetch + extract orchestration; dedupes in-flight IDs; `ingestAllPending()` runs at launch/foreground. `handleSavePress(urlString:)` is the save entry point for intents and the in-app add: new URL saves+ingests, a repeat press within 12 s may send to Kindle (see `send-to-kindle.md`), any other repeat press is ignored. After successful `saveContent`, notifies `ArticleSendCoordinator.articleBecameReady`. New-save automation (auto-share to always-friends `fireAutoShares` + `armSemanticSuggestionIfNeeded`) is factored out and shared with `saveNewWithContent(urlString:content:)` — the latter persists already-fetched content directly (used by the pasteboard suggestion so tapping opens instantly without re-fetching).
- **Platform items**: `ingest` routes a recognized platform URL (X/Bluesky/Reddit/TikTok/IG/FB/Spotify/Apple — `PlatformRegistry.detect`) to `ingestPlatformItem` → `.ready` no-content item, NEVER `.failed`. `ReadingListItem` gains `platform`/`platformItemID`/`mediaCreatorName`/`mediaItemTitle`/`mediaSourceService`. See `content-platforms.md`.
- `Clip/ReadingList/PasteboardSuggester.swift` — `PasteboardSuggesting.evaluate(urlString:)` → `PasteboardCandidate?`. Off the main thread: dedupes against the store, detects YouTube (oEmbed metadata → video candidate) else fetches + extracts the article (→ candidate carrying the extracted `ArticleContent` for instant open). Returns nil for non-http URLs, already-saved URLs, or nothing extractable. Protocol + mock + tests (`PasteboardSuggesterTests`).
- `Clip/ReadingList/ArticleFetcher.swift` — `URLSession` GET, Googlebot UA first (soft-paywall bypass: crawler UA + no JS), Safari UA fallback.
- `Clip/ReadingList/ArticleExtractor.swift` — SwiftSoup mini-readability: strips `script/style/nav/header/footer/aside/form/iframe/svg/button`, scores parents by direct `<p>` text length, emits ordered blocks (`paragraph|heading|quote|listItem|image`) with UTF-16 inline link ranges, plus `author`. LAYERED, never fails while any text exists: refined (junk class/role stripping + trailing link-farm trimming; used only when ≥350 chars AND ≥1/3 of basic) → basic (structural-tag stripping only) → JSON-LD `articleBody` override (when it dwarfs the DOM result — React sites ship the article as metadata) → raw body text. Container scoring credits ancestors with decaying weight (readability-style) so per-paragraph div wrappers still resolve to the article container; the winner is then WIDENED upward until it covers ≥60% of the document's paragraph text (CMSs that split the body across sibling slice containers, e.g. itsnicethat).
- `Clip/ReadingList/ArticleContent.swift` — extracted content model (blocks + link ranges).
- `Clip/ReadingList/ReadingListViewController.swift` — home screen (insetGrouped), **FIFO** order within sections. Dynamic sections, top→bottom via `displayOrder` (decoupled from the enum raw values, which stay stable for the persisted collapsed set): **From Pasteboard** (one-tap suggestion, see below; always expanded), **Reading** (unread, saved <1 week, always expanded), **Read** (collapsed by default, Delete All header button), **Archive** (unread, >1 week by save date, collapsed by default), **Couldn't Load** (failed items, red header + red rows, collapsed by default, at the very bottom). Collapsible headers toggle on tap (chevron; collapsed set persisted in `readingListCollapsedSections`, defaults `[read, archive, error]`). Rows use a custom `ReadingListItemCell` (title + subtitle + a 96×54 thumbnail well). The thumbnail has three states: a **spinner** while the item is still being fetched (state `.pending`), the fetched **art** (decoded off-main, guarded by a reuse key; aspect-fit, switching to aspect-fill only when the ratio is beyond 2× the well's so the smaller dimension always fills ≥ half), or the **platform-logo fallback** (full-color favicon-derived PNG, or an SF glyph) once the fetch finished with no image. Articles attempt an `og:image`/`twitter:image` cover during ingest (`LeadImageExtractor`). The **From Pasteboard** row shows a spinner while the preview is fetched, then the candidate's resolved thumbnail (`PasteboardCandidate.thumbnail` — cover art / video still / platform art); tapping the row PREVIEWS it (transient, unsaved) and a trailing **Save** button (`plus.circle.fill`) saves it explicitly. Rows show host · date · reading time · progress %, plus **"from <friend>"** in the accent color (`secondaryAttributedText`); failed rows read in red and show "pull to retry". The pasteboard Save button is set as BOTH `accessoryView` and `editingAccessoryView` (the list can be editing, which hides the plain accessoryView). **Edit mode is on-demand** (no permanent handles): the long-press menu's bottom item **"Edit List"** calls `setEditing(true)` → selection radios (`allowsMultipleSelectionDuringEditing`), drag-anywhere reorder within Reading via `UITableViewDrag/DropDelegate` (no handle; persists `setOrder`, `isApplyingReorder`-guarded), and the top bar becomes (right→left) **Done / Select All / Delete Selected**; Done exits + clears. `didSelectRowAt` no-ops while editing (tap toggles the radio). Long-press menu (Send to Friend / Send to Kindle / Send to Boox / Share Link / Download Media to Photos [X/Instagram/TikTok — see `media-download.md`] / Share eBook / Delete / **Edit List**) is suppressed for the pasteboard row; **Delete animates** via `deleteItemAnimated` (`deleteRows`/`deleteSections`, guarded by `isAnimatingRowChange`) instead of a full reload. `+` paste-a-URL alert, tap → ReaderViewController, pull-to-refresh retries failures. A header **Articles / Media & Links** segmented filter (`ListFilter`) shows only when the list has both kinds: *Articles* = anything that opens in the text reader (`rendersAsReader` — `contentPlatform == nil && !isYouTubeVideo`: articles, documents, emails); *Media & Links* = everything else (YouTube, platform posts, music/podcasts). Hidden (and reset to All) otherwise. A **catch-up** button (`rectangle.stack`) is pinned to the "Reading List" large-title row (a nav-bar subview, re-pinned each `viewWillAppear`), with a red "action needed" dot when there are unread items; it opens the swipe-through catch-up experience (see `catch-up.md`) and is hidden in edit mode. `ReadingListStore.bump` re-sorts a bumped item to the top of the list. Media download (X/IG/TikTok) progress/result shows in a **non-blocking bottom pill** (`MediaDownloadStatusView`, `isUserInteractionEnabled=false`, a subview of the list so it never appears over the reader) and continues via a `beginBackgroundTask` if the app is backgrounded. The non-article open routing is factored into `openItem(_:presentingFrom:)` so catch-up can reuse it. SIMULATOR-ONLY: each cell has a bottom-left "Row actions" button (`setSimulatorMenu`, `AppEnvironment.isSimulator`) that opens the long-press menu on a plain tap (see `simulator-testing.md`).
  - **Pasteboard suggestion**: on `didBecomeActive` (launch + every foreground) `checkPasteboard()` reads a clipboard URL — gated on `UIPasteboard.changeCount` so the system paste banner shows at most once per newly copied URL — and asks `PasteboardSuggester` whether it's readable. If so, `pasteboardCandidate` renders as a transient (unsaved) row under "From Pasteboard". Tapping `openPasteboardCandidate()` saves it (article: `saveNewWithContent` with the cached content; video: `handleSavePress`) and opens the reader/video; the row vanishes and the item lands in its normal section. Already-saved URLs are never suggested.
- `Clip/ReadingList/SafariURLStore.swift` — reads `lastSafariURL`/`lastSafariURLDate` App Group defaults written by the ClipSafari extension.
- `ShareKit/` — share-sheet logic shared by BOTH extension targets (sync folder group, member of `ClipShare` + `Clip Action Extension`). `ShareViewController` (plain zero-UI `UIViewController`): matches document types (pdf/rtf/text) BEFORE the generic `public.url` so shared PDFs (which also conform to a file-url) aren't dropped by the URL branch; `SharedReadingListAppender` appends a pending item to the App Group JSON (mirror `ReadingListItem` fields). For shared **plain text** and **.txt files**, `ShareKit/ShareTextURL.extract` first checks whether the text is really "just a link" — the whole thing is one URL plus whitespace/punctuation, OR it's short (≤200 chars) and starts with a URL — and if so imports only that URL, dropping the surrounding text. Also: (a) if launched from a Queue friend suggestion (`INSendMessageIntent`, conversation id = friend UUID), queues the URL via `pendingFriendShares.json` for the main app to send (see `social-sharing.md`); (b) the share extension always saves silently (no reader); the action extension routes via `presentSavedOrReader` — articles → `ShareReaderViewController` (with `ExtensionReaderShareProvider` for end-of-article friend-share), non-textual URLs (YouTube, via `NonTextualContent`) → `SavedNonTextualViewController` (embed + "Open in Queue"). See `readers.md`.
- `ClipShare/` — share extension (`com.hpiddy.clip.share`, `NSExtensionPointIdentifier` = `com.apple.share-services`, activation: 1 web URL or 1 file). Uses `ShareKit` as principal class.
- `Clip Action Extension/` — action extension ("Read in Queue"; `com.hpiddy.clip.Clip-Action-Extension`, `NSExtensionPointIdentifier` = `com.apple.ui-services`, `NSExtensionPrincipalClass` = `$(PRODUCT_MODULE_NAME).ShareViewController`, activation: 1 web URL or 1 file). Same `ShareKit` code as the share extension; appears as a separate share-sheet action row and opens the reader (articles) or a playback/open-in-app screen (non-textual). Own App Group entitlement + AppIcon; links SwiftSoup; shares `ReaderKit` + `ShareKit` sync groups. **Ships `GetURL.js` + `NSExtensionJavaScriptPreprocessingFile`**: a `com.apple.ui-services` action extension gets no usable web URL from Safari without it — the URL arrives as the JS result in a `UTType.propertyList` attachment (`NSExtensionJavaScriptPreprocessingResultsKey` → `{URL,title}`), which `ShareViewController.handleJavaScriptResult` reads. `public.url`/file branches still cover non-Safari hosts.
