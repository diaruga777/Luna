# Run a Mac command from Luna Vault

## Outcome and feasibility

Build a Vault action that sends Bash source, text arguments and optional files from iPhone to the user's paired Luna Mac. The Mac stages the files, runs the command as the logged-in user, and retains its exit status, console output, optional text result and returned files. Vault and Shortcuts are two clients of the same job API. A Mac must be awake, reachable and running Luna Mac to accept work. Once the Mac has accepted a fully staged job, the iPhone can disconnect.

All three requested workflows fit this model. The current Mac target disables App Sandbox and already runs external processes. Vault already imports and exports Shortcuts files, and Music already accepts a local audio file. On this Mac a local Bash/ffmpeg smoke check produced a valid-sized M4A from a WAV whose path contained a space and an apostrophe. The installed Codex and Claude CLIs expose noninteractive and resume modes. Cross-device execution, real CLI authentication under the signed companion and the Shortcuts interaction remain implementation acceptance tests.

## User choices and proposed defaults

The following choices are proposals pending the product owner's answers.

| Decision | Proposed first release | What changes with the other choice |
| --- | --- | --- |
| Agent interaction | Run one prompt, follow its output in Vault, send another turn with the CLI's explicit saved session ID. | An interactive Codex or Claude terminal adds a Mac pseudoterminal (PTY), input, resize, disconnect/reattach semantics, and an iPhone terminal renderer. Budget it separately if interactive approvals or full-screen TUIs are essential. |
| Attachment destinations | Accept named paths relative to a private per-job directory. Bash can explicitly move an input into a project. | Exact host destinations need target resolution, permissions, collision and overwrite behavior, plus a definition of what remains on failure. |
| Authority | The user enables commands and approves each Vault installation once on the Mac. That phone can run subsequent Shortcuts while unlocked. | Approving the existing synced account also admits other devices with that credential. Per-run Mac approval makes unattended Shortcuts impractical. |
| Long jobs | Offer a bounded inline wait and a durable job handle with later collection. | A single long foreground flow can be added for convenience. iOS can suspend a Shortcut or the app, so recovery by job ID is still required. |

## Caller contract

**Run Mac Command** accepts multiline Bash source, an ordered list of text arguments, an ordered list of files, optional matching relative input paths, and optional ordered relative output paths. The default working directory is the job directory. A script targeting an existing project can explicitly change directory using a quoted text argument.

1. Bind text arguments to Bash positional parameters. Authors write `"$1"` for a URL or prompt. Never paste a Shortcut variable's value into executable source. The command string itself is executable and supplied by the caller.
2. Use named Bash variables as path annotations. For example, attachment 1 plus input path `camera/take 1.mov` becomes a real file at `<job>/inputs/camera/take 1.mov`. The reference `"$LUNA_INPUT_1"` expands to that absolute path as one argument. Default to the supplied basename under a unique per-slot directory when no path is supplied. Define output slots analogously under `<job>/outputs/`; create parents before launch. Preserve spaces, quotes and Unicode without rewriting Bash syntax.
3. Validate the manifest before launch. Reject missing or mismatched slots, malformed relative paths, traversal, file/directory conflicts, and names colliding under the actual volume's case and Unicode rules. Stage inputs atomically. Open paths relative to owned directory descriptors, refuse symlink traversal and special files, and export snapshots of regular output files. A staging directory organizes files. Bash itself has the Mac user's effective access.
4. Keep the raw stdout and stderr streams, an ordered transcript of chunks as observed with stream labels, and normal exit code or signal. Global write order across independent pipes is unknowable. Offer a distinct optional UTF-8 text result at `"$LUNA_RESULT_TEXT"`. An intentionally empty result stays empty. When absent, stdout is the default text result for text commands. A binary stdout stream is retrievable as a file. Outputs can coexist in the same job and filenames or URLs printed in logs never trigger an implicit file read.
5. Return a stable `MacCommandJob` App Entity with owner/Mac-scoped ID, state, timestamps, exit details and result availability. Shortcuts gets one primary typed value per action. Give it **Get Mac Command Text** (result or console), **Get Mac Command Files** (one or more `IntentFile` values, in declared order), and a status/refresh operation. Provide full console export as a file when text exceeds a documented inline bound. A missing declared output, a nonzero exit and a transport failure must be distinguishable. Let the caller inspect diagnostics after failure.
6. Run can wait briefly for a small job or return the handle as soon as it is staged and accepted. For a large input, persist a local pending job and staged file handles/copies before claiming progress. Surface “waiting to upload” separately from “accepted by Mac”. Provide a way to find recent jobs from a fresh Shortcut if the original invocation ended before delivering a handle. Retrieval actions can wait briefly, report pending and resume later without re-execution. The foreground Vault UI can follow a job to completion. Do not depend on Shortcuts automatically resuming an interrupted sequence.

Apple documents file-based intent parameters and system control over background execution. The installed Xcode 27.1 beta SDK marks `LongRunningIntent` as iOS 27+. The baseline must compile against the stable release toolchain and work on iOS 26. Foreground-started continued processing may improve transfers initiated in Vault. It does not guarantee a background-launched Shortcut can wait indefinitely. [IntentFile](https://developer.apple.com/documentation/appintents/intentfile) · [App Intent runtime](https://developer.apple.com/documentation/appintents/configuring-the-runtime-behavior-of-your-app-intents) · [LongRunningIntent](https://developer.apple.com/documentation/appintents/longrunningintent) · [Continued processing](https://developer.apple.com/documentation/backgroundtasks/performing-long-running-tasks-on-ios-and-ipados)

## Mac execution, transfer and recovery

- Make command access a separate opt-in on Luna Mac. For the per-device proposal, issue a random command credential after explicit Mac approval over the paired channel. Store it in Vault's private, non-synchronizing, device-only Keychain with unlocked-device access. Store its verifier on the Mac, bind grants to the current paired identity/generation, and enforce ownership on submission, input transfer, logs, cancellation and results. Existing pairing alone cannot authorize shell access. Provide revoke/disable in Luna Mac, expire unclaimed grants, and invalidate grants on pairing reset. Revocation stops affected live jobs and closes result access. Require device authentication for sensitive intents. Keep tokens, scripts, prompts, signed URLs and console contents out of diagnostic logs.
- Start with a capability probe. An older or disabled companion should give a specific actionable response. Keep individual control RPCs brief. Allocate a client job UUID before network I/O and persist it. Bind it to the request manifest digest and owner. A duplicate create/commit for the same payload returns the existing job. Reject reuse with different content.
- Persist job state and immutable files under a private Application Support directory outside the synced Vault. Reserve/stage → verify all inputs → commit → launch → collect outputs → terminal state. Track pending, running, succeeded, failed, cancelled, interrupted and expired. Use transactional launch claims. After an ambiguous crash at spawn, mark interrupted and require an explicit new run. A lost reply must never run a side-effecting command twice.
- Model upload on existing reverse BEP requests. The phone stages a security-scoped input while it has access, advertises job-scoped attachment IDs, lengths and digests, then serves bounded verified blocks to the authorized Mac only. Resume at verified blocks. For results the phone pulls ranges by opaque artifact ID, verifies length and digest and atomically publishes local disk-backed files. Never encode media in the command, service request name or JSON. Keep command artifacts out of Vault sync indexes, Spotlight and shared history. Give returned files a documented lifetime long enough for the next Shortcuts action.
- Run the user's Bash source as a file using system Bash, with positional arguments passed separately, a predictable working directory, closed stdin and no automatic profile sourcing. Set HOME and an explicit configurable executable search path for both Homebrew layouts, user-installed tools and app-bundled executables. Finder-launched Luna Mac can have a different PATH and different macOS privacy grants from Terminal. Surface missing tools, login required and filesystem permission failures. Rely on the Mac user's existing CLI login; allow configuring executable directories on the Mac.
- Drain stdout and stderr concurrently into disk-backed logs, page them by cursor and stream readable text in Vault. Support cancellation of the owned process group and handle child processes holding pipes open. A disconnected phone detaches; only explicit cancellation, revocation or a documented resource limit stops the job. On companion quit/restart reconcile unfinished jobs and preserve completed artifacts until expiry.
- Give users a visible retention window and a delete action. Set finite disk, transcript, runtime and concurrency budgets with free-space checks at both ends. Keep full console output within the documented job budget. If a limit is reached, stop the job and record the reason and captured byte count. Never silently substitute an abbreviated preview for the full transcript.

## Three acceptance Shortcuts

| Workflow | Command and handoff | What to prove |
| --- | --- | --- |
| YouTube → Music | Pass the source URL as text argument 1. Declare `audio.m4a` as an output. Run `yt-dlp --no-playlist -x --audio-format m4a -P "$(dirname "$LUNA_OUTPUT_1")" -o 'audio.%(ext)s' -- "$1"`. Collect the first returned file and pass it to Music's **Add Audio to Podcasts**, using a stable source ID as the import key. | With an authorized media fixture, confirm Music copies and queues playable audio once even if the import is retried. The existing dedicated Music downloader remains independently usable. |
| URL-only variant | Run `yt-dlp --no-playlist -f bestaudio -g -- "$1"`. Read stdout as text. For a URL the iPhone can fetch, use Shortcuts **Get Contents of URL**, then pass the downloaded file to **Add Audio to Podcasts**. | Distinguish a source-issued link from a Mac file path. A media URL can expire or need headers or the Mac's network address. Use Mac file return when that happens. Direct URL ingestion by the Music action would be a separate Music change. |
| Codex or Claude | Pass the prompt and project directory as text arguments. In the chosen project, use `codex exec --json -o "$LUNA_RESULT_TEXT" -- "$1"`, or `claude -p -- "$1"`. The first gives machine-readable events and the final answer separately; for Claude's default text output, stdout is the answer. Persist the explicit CLI session ID when a Shortcut needs another turn, using the CLI's JSON event/result mode to obtain it. | Send a second prompt to the same project and explicit session using `codex exec resume` or `claude -p --resume`. Verify two simultaneous conversations stay separate. Check login and permission behavior when launched by Luna Mac. Interactive approval requires the PTY option or a separate CLI-specific integration. [Claude CLI](https://code.claude.com/docs/en/headless) |
| Media → ffmpeg → Files | Pick a video; supply it as file 1 and declare `track.m4a` as output 1. Run `ffmpeg -nostdin -i "$LUNA_INPUT_1" -vn -c:a aac "$LUNA_OUTPUT_1"`. Feed the returned file to **Save File** or Music. | Verify playable audio, preserved filename and a readable transcript. Repeat with two inputs, several declared outputs, a filename containing quotes, and an interrupted transfer. |

For long work, the first Shortcut can start the job and a second can find it, check completion and perform the handoff. When one foreground run completes within the available time, the same Shortcut can do all steps. No public download server is required.

## Implementation sequence and verification

1. **Prove the user-facing contract.** On an iOS 26 simulator and the stable release SDK, expose a thin intent over a fixture job. In the Shortcuts editor exercise text, zero/one/multiple files, typed job properties, status refresh, and handing one returned audio file to Music. Try foreground and cold background invocation. Verify how the system hands off large provider-backed files and choose an explicit foreground continuation for cases that cannot stage inline. Resolve the three product decisions above before committing a UI or protocol that depends on them.
2. **Deliver a vertical slice.** Add capability discovery, command grants, revocation, persistent job IDs, the Mac runner and one Vault submit/status/result flow. Execute a short Bash command with both output streams and a distinct text response over the existing paired connection. Test disabled, unauthorized, expired/revoked and older peers. Send duplicate concurrent commits and drop the acknowledgement after launch; verify one invocation.
3. **Add attachments and results.** Implement the private job directory, verified chunk exchange, status, immutable results, retention, cleanup and cancellation. Exercise zero-byte files, multi-gigabyte media with bounded memory, disk-full and quota errors, duplicate names, symlinks, changed input, lost blocks and reconnection. Characterize large file performance on LAN and one supported remote route.
4. **Ship both entry points.** In Vault add a Mac Commands screen with a command editor, arguments, attachment/path mapping, output declarations, progress, live console, returned text/files, cancellation and recent jobs. Expose the same operations to Shortcuts, including finding an interrupted run and downloading its full transcript. Update Vault's automation descriptions and feature docs. Run the three example workflows through the actual actions. If a live terminal is selected, add a separate interactive session action/screen with Mac-side PTY lifecycle, input/resize and replay or screen reconstruction on reattachment. Shortcuts can start or refer to a session; ongoing terminal interaction belongs in Vault.
5. **Verify lifecycle and compatibility.** Exercise screen lock, phone suspension/relaunch, companion quit/relaunch, switching networks mid-transfer, Mac sleep, unpair/re-pair and cancellation of a command with a child. Confirm existing Vault sync, browsing and Music's dedicated download still pass with mixed-version peers. Use the repository's stable signing identity, bundle identifier and existing install path for any Mac build used on this Mac. Use simulator tools or manual iPhone checks under the repository's device automation rule.

The release gate is a real Shortcut taking a file from another app, running a command through the signed Mac companion, returning both its console and a playable disk-backed result, and handing that result to the next action. Repeat after disconnecting the phone during execution and confirm the Mac ran the command exactly once in that test.
